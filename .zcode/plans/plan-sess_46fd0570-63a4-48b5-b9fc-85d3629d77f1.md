# Предзаказ при бронировании столика (банкетный модуль)

## 1. База данных — `db/manager.py`, новая миграция `migrate_v4()`

Расширяем таблицу `reservations` (новые колонки через ALTER TABLE ... с проверкой наличия):
- `guests_count INTEGER DEFAULT 0` — количество гостей
- `is_closed_event INTEGER DEFAULT 0` — галочка «Закрытое мероприятие»
- `advance_amount REAL DEFAULT 0`, `advance_method TEXT` — аванс одной строкой (метод: cash/card/transfer/«наличные+карта» и т.п.)
- `order_json TEXT` — состав предзаказа (позиции, кол-во, цены на момент заказа)

Новые категории в справочнике меню: **«Il Drive (Окно)»** и **«Банкетное меню»** — вносятся как обычные позиции через существующую `form_menu.html`; в форме предзаказа они отображаются отдельными вкладками вместе со всеми остальными категориями (всё меню целиком, построчно).

## 2. Backend — `api/main.py`

- **POST `/api/reservations/order`** — создать/обновить бронь с предзаказом: все поля брони + `guests_count`, `is_closed_event`, `items_json`, `advance_amount`, `advance_method`. При `is_closed_event=1` автоматически создаёт брони на **все столики** `1..get_max_table()` на это время (одна «мастер»-бронь + служебные на остальные столы, чтобы зал считался занятым).
- **GET `/api/reservations/order?res_id=`** — получить бронь с составом заказа (для повторного открытия/редактирования).
- **GET `/api/reservations/order_pdf?res_id=`** — PDF по образцу `feedback_day_pdf` (reportlab, Arial из C:\Windows\Fonts): шапка (дата/время, столик, гость, телефон, кол-во гостей, метка «ЗАКРЫТОЕ МЕРОПРИЯТИЕ»), построчно позиции × кол-во = сумма, итог, аванс, метод оплаты, к оплате. Сохранение в папку `reports/` (REPORTS_DIR), отдаётся FileResponse.
- **GET `/api/reservations/reminders`** — расширяем ответ: добавляем `day_before` (за сутки), `morning` (на утро дня брони), `due_soon_2h` (за 2 часа). Существующий интервал 60 мин сохраняем.

## 3. Форма предзаказа — `templates/waiter_pos.html`

В модалке брони (после выбора столика/времени, полей телефон+имя) добавляем кнопку **«Заказ»**. Она открывает новое полноэкранное окно-оверлей (стили копируем с чеков гостевого меню: `.receipt-*`, палитра проекта, оверлей + белая коробка с радиусом 12px):

- **Вверху**: итоговая стоимость заказа, количество гостей (input), галочка «Закрытое мероприятие».
- **Список меню**: выпадающий список/вкладки по категориям — все категории из `/api/menu` (бар, кухня, чиры, салаты, Il Drive (Окно), Банкетное меню). Построчно: выбираешь позицию → она попадает в корзину ниже.
- **Корзина = чек**: оформление как чек гостевого меню, у каждой позиции кнопки **− / +** (как `changeQty` в `guest_pos.html`), цена и сумма пересчитываются сразу.
- **Внизу**: аванс (сумма) + выбор оплаты: 💵 Наличные / 💳 Карта / 🏦 Перевод / 🔀 Комбинированная (для комбинированной — ввод нескольких строк метод+сумма, итог сверяется с суммой аванса).
- Кнопки: **«Сформировать PDF»** (открывает `/api/reservations/order_pdf`), **«Сохранить бронь»**.

## 4. Напоминания — `waiter_pos.html` + `default.html`

Расширяем существующий опрос каждые 30 сек (`checkBartenderReminders` / `startBarReminders`): обрабатываем новые ключи `day_before` («Завтра бронь/мероприятие»), `morning` («Сегодня брони на день»), `due_soon_2h` («Через 2 часа мероприятие») — то же всплывающее окно + звук `beep.mp3`. Уведомления видят бармен и директор.

## 5. Директорская форма — `templates/director.html`

Новый блок «Брони и мероприятия»: список броней на день с фильтром, для каждой — состав заказа, аванс, галочка закрытого мероприятия, кнопки «PDF», редактирование. Плюс сюда же дублируется кнопка создания брони с предзаказом (тот же блок кнопок).

## 6. Касса — `templates/default.html`

Добавляем блок «Заказ по брони»: поиск брони (день/телефон/имя), просмотр состава заказа и аванса, кнопка «PDF». Создание заказа — та же форма, что в waiter_pos (переиспользуем разметку/JS).

## 7. Проверка

- Прогон сервера на порту 8099 (как в live_test), создание брони с предзаказом через curl/скриптом: обычная, закрытое мероприятие (проверить, что заняты все столики), аванс комбинированный, PDF создаётся в `reports/`.
- Проверка напоминаний на тестовых временах (сегодня+2ч, завтра).

Порядок работ: миграция БД → backend-эндпоинты → форма в waiter_pos → напоминания → director.html → default.html → тесты.
